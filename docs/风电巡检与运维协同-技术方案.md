# 风电巡检与运维协同智能体系统技术方案

> 项目性质：原创合成案例的课程训练方案，不代表真实客户授权、生产部署或业务验收。
>
> 业务边界：只做只读核对、告警归并建议、检修资料草稿与人工交接；不得自动启停风机、修改保护阈值、替代安全许可或对外作出承诺。

## 1. 项目背景与目标

青原新能源的合成访谈显示：日均告警 280 条、误报率 38%，60 台风机每天约 120 次点检，巡检员每天用于重复归并告警的时间约 3 小时。现有流程为“告警 → 趋势核查 → 现场检查 → 工单派发 → 检修 → 值班确认”，但各节点等待和处理时间尚未分别计量。

项目不以“上线一个万能 AI”为目标，而以可验证的业务结果为目标：

- 在 5 台风机上开展 8 周受控试点，先历史回放，再与现流程并行。
- 重大告警漏报数必须为 0。
- 误报率以 38% 的合成访谈基线为参照，验证 15% 的目标；判定来源和统计口径须先签核。
- 有效告警响应目标为 20 分钟，起算节点须由业务、数据和值班角色共同确认。
- 所有建议均可追溯到原始记录、资料版本、规则或模型版本以及人工确认人。

## 2. 用户、职责与权限

| 角色 | 姓名 | 主要职责 | 权限与限制 |
| --- | --- | --- | --- |
| 运维总监 | 顾明岚 | 业务目标、预算、试点范围、继续或停止 | 批准试点范围；不替代安全专业签核 |
| 风场巡检员 | 林亦舟 | 趋势核查、现场反馈、建议复核 | 可查看授权记录、编辑草稿、退回建议；不能修改原始记录 |
| 检修计划员 | 唐映秋 | 流程、资料校核、工单交接与升级 | 可发起复核；不能代替安全经理审批 |
| SCADA 工程师 | 秦芮 | 只读接口、数据质量、快照与恢复 | 管理数据契约和只读接入；不开放设备控制 |
| 作业安全经理 | 傅景 | 安全、权限、留存、审计与否决 | 对关键风险有否决权；核签人工兜底规则 |
| 电站值班长 | 叶书 | 服务结果、完成口径、争议与反馈 | 参与服务验收；不得重复计算业务完成次数 |

权限原则：按 SCADA、EAM、气象服务分别授权；禁止借用账号；最终决定、资产变更和对外承诺必须由具名审批人完成。

## 3. 最小试点与方案取舍

### 3.1 最小业务闭环

1. 读取已授权的 SCADA 事件、EAM 工单、振动谱、检修记录、作业票和气象快照。
2. 通过确定性硬规则校验身份、模块范围、必填字段、资料版本、数据新鲜度和权限。
3. 对同设备、同业务编号、同时间窗的告警先执行确定性去重。
4. 模型只处理跨文本相似告警聚类、资料摘要和待确认项提示，并输出事实引用。
5. 巡检员或检修计划员人工确认、修改或退回草稿。
6. 接手人确认后才结束上一岗位待办，审计记录保留完整链路。

### 3.2 方案比较

- **人工模板优化**：立即统一资料模板、唯一业务编号、交接确认和指标分母；成本低，但无法充分降低大量重复归并工作。
- **确定性规则**：负责权限、数据质量、版本、时间窗和幂等，是系统首选底座，不向模型让渡硬约束。
- **模型辅助**：只在规则底座上提供相似聚类和摘要；必须证明增量收益高于人工复核与运行成本，否则移除模型仍应可运行。

首期排除自动派单、自动启停、保护阈值修改、自动安全许可、资产变更、自动对外承诺和全风场直接推广。

## 4. 总体架构

```text
SCADA / EAM / 振动谱 / 作业票 / 气象快照
                    │ 只读、分系统授权
                    ▼
          接入适配与数据质量校验
       主编号 / 事件时间 / 版本 / 新鲜度
                    │
                    ▼
        安全、权限、范围等确定性硬规则
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
   告警确定性去重        模型聚类与资料草稿
          └─────────┬─────────┘
                    ▼
          来源可追溯的建议与草稿
                    ▼
          人工复核、交接、签核与审计
```

系统默认不写入业务系统。任何新增写权限必须重新经过需求、风险、权限和验收评审，不得通过修改提示词隐式开放。

## 5. 数据契约

### 5.1 核心字段

| 字段 | 说明 | 失败处理 |
| --- | --- | --- |
| `business_id` | 全流程唯一业务编号 | 缺失则拒绝归并并转人工 |
| `turbine_id` | 风机或设备主编号 | 主数据不匹配则进入修复队列 |
| `event_time` | 原始事件时间及来源时区 | 时钟冲突不得自动选择时间 |
| `source_id` | 原始资料唯一标识 | 无来源不生成建议 |
| `source_version` | 资料版本、生效日期和适用范围 | 冲突时同时保留版本并交人工 |
| `observed_at` | 快照获取时间 | 超过一个更新周期标为待刷新 |
| `permission_scope` | 当前身份可访问范围 | 越权请求直接阻止并审计 |
| `idempotency_key` | 业务编号、输入版本和操作类型的组合 | 重复请求不得重复生成待办 |

### 5.2 数据质量与降级

- 时钟偏差、传感器替换记录不全、停机原因混填等歧义数据进入人工修复队列，不进入自动推荐样本。
- 授权业务状态每日更新两次；超过一个更新周期的信息标为“待刷新”，不得作为实时承诺。
- 接口中断时仅展示带时间戳的上一份只读快照，并明确“暂未更新”。
- 重连后按业务编号去重补齐，不重复触发待办，现有人工流程持续可用。
- 本轮评价记录暂按 90 天设计留存演练；真实保存、归档和删除期限必须服从组织制度。

## 6. 需求与验收追踪

| 需求 | 内容 | 关键验收 |
| --- | --- | --- |
| REQ-01 | 告警归并与原记录追溯 | 每条建议可展开原记录；重大漏报为 0；无来源则拒绝 |
| REQ-02 | 数据质量和新鲜度 | 歧义记录进入修复队列；超期数据明确标记 |
| REQ-03 | 检修资料草稿 | 包含业务编号、版本、引用、未结项；不得覆盖原记录 |
| REQ-04 | 人工交接与审计 | 接手确认后关闭；保留原因、时间、改动和签核人 |
| REQ-05 | 指标与反馈闭环 | 固定分母和排除规则；同一业务不重复计成功；每周复盘 |

拒绝条件：任何重大告警漏报、越权访问、自动设备控制、来源不可追溯、安全事项自动判断，或转人工时缺少触发原因、接手人和确认时间。

## 7. 统一接口与错误约定

所有对外接口统一返回：

```json
{
  "ok": true,
  "data": {},
  "error": {
    "code": "",
    "msg": ""
  }
}
```

失败时 `ok=false`，`data=null`，`error.code` 使用稳定机器码，`error.msg` 使用可供操作人员理解的中文说明。建议错误码包括 `VALIDATION_ERROR`、`PERMISSION_DENIED`、`SOURCE_MISSING`、`VERSION_CONFLICT`、`SOURCE_STALE`、`SOURCE_UNAVAILABLE`、`DUPLICATE_REQUEST`、`HUMAN_REVIEW_REQUIRED` 和 `INTERNAL_ERROR`。

正常建议状态使用 `review`，材料缺失使用 `needs-info`，版本冲突使用 `manual`，无权限或越界使用 `blocked`，来源中断使用 `degraded`。业务状态与 HTTP 状态码分别定义，不以 HTTP 200 暗示业务成功。

## 8. 测试与发布

### 8.1 技术评估

至少覆盖正常业务、材料缺失、版本冲突、身份无权限、来源不可用、越界动作、未知样本和跨模块请求。所有合成技术用例均应检查 `writes=0`、`externalSends=0` 以及来源和审计轨迹。

### 8.2 业务评估

技术用例不能替代真实业务验收。业务评估须使用脱敏历史回放和 5 台 8 周并行样本，覆盖重大故障、特殊天气、时钟偏差、字段缺失、版本冲突、交接争议和重复请求，并固定指标分母、起算点和排除规则。

### 8.3 发布与回滚

- 固定输入、规则、模型、依赖和资产哈希。
- 上线前重跑全部技术与业务回归用例。
- 先回放，再 5 台灰度并行；真实发布窗口和变更单另行签核。
- 出现重大漏报、越权、控制请求、来源断链、重复待办或兜底失效时立即停用建议并恢复原人工流程。
- 回滚后按业务编号核对补录和去重，完成安全、技术、服务和业务四方复核后才可恢复。

## 9. ROI 与投入决策

训练敏感性测算采用以下**假设**，不是客户报价或收益承诺：一次性投入 25 万元，每月运行费 2000 元，综合时薪 80 元，每月 30 天，工时兑现比例 50%，仅以每天约 3 小时重复归并工时测算。

- 每月可兑现收益：`3 × 30 × 80 × 50% = 3600 元`。
- 每月净收益：`3600 - 2000 = 1600 元`。
- 首年总投入：`250000 + 12 × 2000 = 274000 元`。
- 首年毛收益：`3 × 30 × 80 × 50% × 12 = 43200 元`。
- 首年净收益：`43200 - 274000 = -230800 元`。
- 首年 ROI：约 `-84.2%`；静态回本约 `156.3` 个月。

因此，保守假设下不支持直接全量采购，只支持受控验证。节省工时不等于现金回款，维护、模型、服务器和新增复核成本必须扣除。

## 10. 30/60/90 天运营计划

- **每日**：秦芮检查接口、数据质量、快照和权限；一线记录漏报、误判、改动、响应与交接等待。
- **每周**：叶书复核服务结果，傅景抽查审计与兜底，顾明岚指定改进责任人。
- **30 天**：复核基线、误报判定、响应起算点和采用障碍。
- **60 天**：复核误报目标、工时变化、真实成本与规则漂移。
- **90 天**：决定继续、扩展、缩减或退役，并完成资料归档或删除复核。

下一轮优先补真实脱敏评估集、重大漏报标注、指标口径、数据质量修复和转人工岗位映射，而不是优先扩展设备控制或自动派单。
