# 风电巡检与运维协同智能体系统技术方案（MVP 优化版）

> 项目性质：原创合成案例的课程训练方案，不代表真实客户授权、生产部署或业务验收。
>
> 业务边界：只做只读核对、告警归并建议、检修资料草稿与人工交接；不得自动启停风机、修改保护阈值、替代安全许可或对外作出承诺。
>
> MVP 输入：FastAPI、Harness、RAG、LLM Wiki（知识图谱）、SaaS 管理员、分层用户权限，以及面向外部开源仓库的 1 个 Issue 和 1 个 PR。

## 1. 项目背景与目标

青原新能源的合成访谈显示：日均告警 280 条、误报率 38%，60 台风机每天约 120 次点检，巡检员每天用于重复归并告警的时间约 3 小时。现有流程为“告警 → 趋势核查 → 现场检查 → 工单派发 → 检修 → 值班确认”，但各节点等待和处理时间尚未分别计量。

项目不以“上线一个万能 AI”为目标，而以可验证的业务结果为目标：

- 在 5 台风机上开展 8 周受控试点，先历史回放，再与现流程并行。
- 重大告警漏报数必须为 0。
- 误报率以 38% 的合成访谈基线为参照，验证 15% 的目标；判定来源和统计口径须先签核。
- 有效告警响应目标为 20 分钟，起算节点须由业务、数据和值班角色共同确认。
- 所有建议均可追溯到原始记录、资料版本、规则或模型版本以及人工确认人。

## 2. MVP 范围与不做事项

### 2.1 本期必须交付

1. **FastAPI 服务**：统一接口、配置、错误结构、审计字段和自测入口。
2. **轻量 Agent Harness**：用显式状态机编排范围校验、检索、规则判断、草稿和人工确认，不引入不可控自主循环。
3. **知识库**：RAG 检索、LLM Wiki 页面和知识图谱关系统一保留来源、版本与租户边界。
4. **SaaS 权限**：平台管理员、组织管理员和分层业务用户，实施组织、角色和数据范围三层隔离。
5. **最小业务闭环**：合成资料读取、告警去重、带来源草稿、人工复核和审计。
6. **开源协作成果**：针对同一个真实问题，向确认后的外部仓库提交 1 个高质量 Issue 和 1 个关联 PR。

### 2.2 本期明确不做

- 不接入真实设备控制，不写 SCADA，不自动修改 EAM 正式工单。
- 不引入 Harness.io、Neo4j、独立向量数据库、LangChain、消息队列或 Kubernetes。
- 不做无限自主规划、自动外发、自动合并 PR 或跨租户检索。
- 不用模型生成内容替代原始证据，不把合成测试当作真实客户验收。

## 3. 用户、职责与 SaaS 分层权限

| 层级或角色 | 主要职责 | 数据范围与限制 |
| --- | --- | --- |
| 平台管理员 | 管理组织、系统开关和平台级配置 | 默认不能查看各组织业务正文；敏感操作单独审计 |
| 组织管理员 | 管理本组织用户、角色、知识库和授权范围 | 仅限本组织；不因管理员身份获得安全或业务审批权 |
| 运维总监（顾明岚） | 业务目标、预算、试点范围、继续或停止 | 批准本组织试点；不替代安全专业签核 |
| 风场巡检员（林亦舟） | 趋势核查、现场反馈、建议复核 | 仅授权风场；可编辑草稿、退回建议，不能修改原始记录 |
| 检修计划员（唐映秋） | 流程、资料校核、工单交接与升级 | 可发起复核；不能代替安全经理审批 |
| SCADA 工程师（秦芮） | 只读接口、数据质量、快照与恢复 | 管理数据契约和只读接入；不开放设备控制 |
| 作业安全经理（傅景） | 安全、权限、留存、审计与否决 | 对关键风险有否决权；核签人工兜底规则 |
| 电站值班长（叶书） | 服务结果、完成口径、争议与反馈 | 参与服务验收；不得重复计算业务完成次数 |

权限判断必须同时满足：`org_id` 属于当前组织、角色允许该动作、数据范围覆盖目标风场或资料。所有业务表必须带 `org_id`，所有查询在服务端强制过滤，不能依赖前端隐藏按钮。

平台管理员与组织管理员只承担管理职责，不自动获得业务审批权。最终决定、资产变更、对外承诺、高空作业、停送电和天气禁限必须由对应授权人员完成。

## 4. 最小业务闭环与方案取舍

### 4.1 最小业务闭环

1. 读取当前组织已授权的 SCADA 事件、EAM 工单、振动谱、检修记录、作业票和气象快照。
2. 通过确定性硬规则校验组织、身份、模块范围、必填字段、资料版本、数据新鲜度和权限。
3. 对同设备、同业务编号、同时间窗的告警先执行确定性去重。
4. Harness 调用 RAG 获取相关资料，再让模型生成相似聚类、资料摘要和待确认项提示。
5. 每条模型结论必须返回原记录引用；证据不足时返回 `needs-info` 或 `manual`，不能补写事实。
6. 巡检员或检修计划员人工确认、修改或退回草稿。
7. 接手人确认后才结束上一岗位待办，审计记录保留完整链路。

### 4.2 方案比较

- **人工模板优化**：统一资料模板、唯一业务编号、交接确认和指标分母；成本低，但无法充分降低大量重复归并工作。
- **确定性规则**：负责租户、权限、数据质量、版本、时间窗和幂等，是系统首选底座，不向模型让渡硬约束。
- **模型辅助**：只在规则底座上提供相似聚类和摘要；必须证明增量收益高于人工复核与运行成本，否则移除模型仍应可运行。

## 5. 总体架构与技术栈

```text
React + TypeScript + Vite
              │
              ▼
       FastAPI / Pydantic
   统一响应、认证、SaaS 权限、审计
              │
              ▼
       轻量 Agent Harness
  范围校验 → 规则校验 → RAG → 草稿 → 人工关卡
              │
      ┌───────┴────────┐
      ▼                ▼
 确定性去重        RAG + LLM Wiki + 知识图谱
      │                │
      └───────┬────────┘
              ▼
   SQLAlchemy 2.0 + SQLite
 文档、分块、向量、Wiki、图关系、运行与审计
```

技术栈固定为：Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2.0、SQLite、React 18、TypeScript、Vite、pytest、httpx、Vitest 和 Ruff。

Harness 在本方案中指项目内实现的轻量智能体运行与评估层，不是额外引入的 Harness.io 平台。模型和 Embedding 均通过标准 HTTP 调用 OpenAI 兼容接口，地址、模型名和密钥只从 `config.yaml` 与环境变量读取。

MVP 使用 NumPy 对 SQLite 中保存的向量做小规模余弦相似度计算，避免引入独立向量数据库；知识图谱使用关系表保存，不引入 Neo4j。数据规模超过 MVP 后再单独评估专用组件。

## 6. Harness 运行设计

### 6.1 显式状态机

```text
received
  → scope_checked
  → permission_checked
  → evidence_checked
  → retrieved
  → draft_generated
  → review          （等待人工）
  → approved / rejected / needs-info

任意阶段 → blocked / degraded / manual
```

每次运行保存 `run_id`、`org_id`、`business_id`、输入哈希、当前状态、规则版本、模型版本、检索引用、输出、人工动作和时间戳。状态只能按白名单迁移，模型不能直接修改状态或调用审批函数。

### 6.2 工具白名单

- `read_authorized_document`：只读当前组织授权资料。
- `search_knowledge`：只检索当前组织和当前数据范围。
- `get_source_chunk`：按引用读取原始分块。
- `create_review_draft`：创建待人工确认草稿，不形成正式业务执行。
- `request_human_review`：创建复核任务并记录责任人。

不提供设备控制、正式工单写入、自动外发、自动合并和用户提权工具。工具超时、返回空值或来源异常必须显式失败，不允许 Harness 自行重试成无限循环；同一操作最多按配置重试，并使用幂等键。

## 7. RAG、LLM Wiki 与知识图谱

### 7.1 数据处理链路

```text
授权文档 → 版本校验 → 清洗与分块 → Embedding → RAG 索引
                         │
                         ├→ 带来源摘要 → LLM Wiki 页面
                         └→ 实体/关系候选 → 人工确认 → 知识图谱
```

建议数据表：`documents`、`document_chunks`、`chunk_embeddings`、`wiki_pages`、`knowledge_nodes`、`knowledge_edges`、`agent_runs`、`review_tasks` 和 `audit_logs`。所有表均包含 `org_id`，文档与分块另含 `source_id`、`source_version` 和 `content_hash`。

### 7.2 RAG 约束

- 检索条件先过滤组织、数据范围、资料版本和有效期，再计算相似度。
- 返回 `chunk_id`、原文摘录、来源、版本和得分；回答必须保留这些引用。
- 无有效资料或低于阈值时返回资料不足，不允许模型依据常识补写业务事实。
- 版本冲突时同时展示两个版本并转人工，不自动选择较新或较宽松条款。

### 7.3 LLM Wiki 约束

Wiki 页面只组织已授权资料中的主题，如“台风前传感器失联处置”“告警归并规则”“人工交接要求”。每段保留来源引用和生成版本；人工修订形成新版本，不覆盖原文或历史页面。

### 7.4 知识图谱约束

核心节点包括风机、告警、业务事件、资料、规则、角色和交接任务；核心关系包括“发生于”“引用”“受约束于”“由谁复核”“交接到”。

模型只能产生关系候选，必须附来源证据。影响安全、权限和业务验收的关系需人工确认后生效；图谱用于导航和解释，不直接触发业务动作。

## 8. 数据契约与降级

| 字段 | 说明 | 失败处理 |
| --- | --- | --- |
| `org_id` | 当前组织租户标识 | 缺失或跨组织直接拒绝 |
| `business_id` | 全流程唯一业务编号 | 缺失则拒绝归并并转人工 |
| `turbine_id` | 风机或设备主编号 | 主数据不匹配则进入修复队列 |
| `event_time` | 原始事件时间及来源时区 | 时钟冲突不得自动选择时间 |
| `source_id` | 原始资料唯一标识 | 无来源不生成建议 |
| `source_version` | 资料版本、生效日期和适用范围 | 冲突时同时保留版本并交人工 |
| `observed_at` | 快照获取时间 | 超过一个更新周期标为待刷新 |
| `permission_scope` | 当前身份可访问范围 | 越权请求直接阻止并审计 |
| `idempotency_key` | 业务编号、输入版本和操作类型的组合 | 重复请求不得重复生成待办 |

时钟偏差、传感器替换记录不全、停机原因混填等歧义数据进入人工修复队列。授权业务状态每日更新两次，超期标为“待刷新”；接口中断只展示带时间戳的只读快照并提示“暂未更新”；重连后按业务编号去重补齐。本轮评价记录暂按 90 天设计留存演练，真实期限必须服从组织制度。

## 9. 需求与验收追踪

| 需求 | 内容 | 关键验收 |
| --- | --- | --- |
| REQ-01 | 告警归并与原记录追溯 | 每条建议可展开原记录；重大漏报为 0；无来源则拒绝 |
| REQ-02 | 数据质量和新鲜度 | 歧义记录进入修复队列；超期数据明确标记 |
| REQ-03 | 检修资料草稿 | 包含业务编号、版本、引用、未结项；不得覆盖原记录 |
| REQ-04 | 人工交接与审计 | 接手确认后关闭；保留原因、时间、改动和签核人 |
| REQ-05 | 指标与反馈闭环 | 固定分母和排除规则；同一业务不重复计成功；每周复盘 |
| REQ-06 | RAG、Wiki 与图谱 | 引用可回到原分块；跨组织不可检索；关系候选需确认 |
| REQ-07 | SaaS 分层权限 | 组织、角色、数据范围三层均通过服务端测试 |
| REQ-08 | Harness 可审查运行 | 状态迁移合法、工具受限、人工不可绕过、失败可复现 |

拒绝条件包括重大告警漏报、跨租户访问、越权、自动设备控制、来源不可追溯、安全事项自动判断，以及转人工缺原因、接手人或确认时间。

## 10. API 与统一错误约定

建议 MVP 接口：

- `GET /api/v1/health`：服务与配置自检，不返回敏感配置。
- `POST /api/v1/documents`：登记授权合成资料，不直接写入业务系统。
- `GET /api/v1/knowledge/search`：当前组织范围内的 RAG 检索。
- `GET /api/v1/wiki/pages` 与 `GET /api/v1/graph/nodes/{id}`：读取 Wiki 和图谱。
- `POST /api/v1/agent/runs`：创建 Harness 运行并返回可追踪 `run_id`。
- `POST /api/v1/reviews/{id}/approve` 与 `/reject`：人工确认或退回。
- `GET /api/v1/audit/runs/{id}`：读取权限范围内的运行审计。
- `POST /api/v1/admin/users`：组织管理员管理本组织用户和数据范围。

所有对外接口统一返回：

```json
{
  "ok": true,
  "data": {},
  "error": {
    "code": "",
    "msg": ""
  }
}
```

失败时 `ok=false`、`data=null`，`error.code` 使用稳定机器码，`error.msg` 使用中文说明。错误码至少包括 `VALIDATION_ERROR`、`TENANT_MISMATCH`、`PERMISSION_DENIED`、`SOURCE_MISSING`、`VERSION_CONFLICT`、`SOURCE_STALE`、`SOURCE_UNAVAILABLE`、`DUPLICATE_REQUEST`、`HUMAN_REVIEW_REQUIRED` 和 `INTERNAL_ERROR`。

正常建议状态使用 `review`，材料缺失使用 `needs-info`，版本冲突使用 `manual`，无权限或越界使用 `blocked`，来源中断使用 `degraded`。业务状态与 HTTP 状态码分别定义，不以 HTTP 200 暗示业务成功。

## 11. MVP 页面与验证清单

最小页面包括登录、业务工作台、知识库检索、Wiki/图谱、Harness 运行详情、人工复核和组织管理。前端只负责展示和提交，所有权限、状态迁移与引用校验由后端重新执行。

| MVP 项 | 必须通过的验证 |
| --- | --- |
| FastAPI | 统一响应、配置不泄密、健康检查和核心接口可运行 |
| Harness | 正常闭环、非法状态迁移拒绝、工具越权拒绝、人工确认不可跳过 |
| RAG | 有来源检索、无来源拒答、版本冲突转人工、跨组织零召回 |
| LLM Wiki | 每段有来源、修订有版本、删除或过期资料不再作为有效依据 |
| 知识图谱 | 节点与边可追溯、候选关系需确认、图谱不触发业务动作 |
| SaaS 权限 | 平台/组织管理员隔离、角色分层、风场数据范围、直接访问 ID 也不能越权 |
| 业务安全 | 8 类基础用例及重复请求全部通过，`writes=0`、`externalSends=0` |

## 12. 测试、发布与运营

技术评估至少覆盖正常业务、材料缺失、版本冲突、身份无权限、跨租户访问、来源不可用、越界动作、提示词注入、未知样本、跨模块请求和重复请求。每次测试固定输入、规则、模型、依赖和资产哈希，保存 expected/actual、引用和审计轨迹。

技术用例不能替代真实业务验收。业务评估须使用脱敏历史回放和 5 台 8 周并行样本，覆盖重大故障、特殊天气、时钟偏差、字段缺失、版本冲突、交接争议和重复请求，并固定指标分母、起算点和排除规则。

发布先回放，再 5 台灰度并行。出现重大漏报、越权、控制请求、来源断链、重复待办或兜底失效时立即停用建议并恢复原人工流程；回滚后完成安全、技术、服务和业务四方复核才可恢复。

运营按每日、每周和 30/60/90 天节奏检查接口、数据质量、漏报、误判、人工改动、响应、交接、采用率、真实成本与规则漂移。下一轮优先补真实脱敏评估集和口径，不优先扩展设备控制。

## 13. ROI 与投入决策

训练敏感性测算采用以下**假设**，不是客户报价或收益承诺：综合时薪 80 元，每月 30 天，工时兑现比例 50%，仅以每天约 3 小时重复归并工时测算，首年毛收益为 `3 × 30 × 80 × 50% × 12 = 43200 元`。

商业化成本拆解得到首年内部成本 274,000 元；该金额不是对外报价。按风险预留和目标加成分别计算，训练报价下限为 361,680 元，上限为 460,320 元。若以最终项目总价 `P` 作为首年全部投入，且不重复扣除已包含的模型、服务器和运维费用，则首年 ROI 为 `(43200 - P) ÷ P`：下限报价情景约为 `-88.1%`，上限报价情景约为 `-90.6%`。

报价区间高于合成访谈的首期预算上限 250,000 元，应先缩小范围、复核成本或重谈预算。保守假设下不支持直接全量采购，只支持受控验证；节省工时不等于现金回款，真实回本周期仍需成交价、续年费用和经签核的收益口径。完整公式与配套表格见《风电巡检与运维协同-商业化测算》。

## 14. 分阶段交付与开源协作

### 阶段一：FastAPI + Harness 最小闭环

完成统一接口、SaaS 基础模型、显式状态机、合成样本、确定性去重、草稿、人工确认和审计。先跑通离线安全测试，再接入模型。

### 阶段二：RAG + LLM Wiki + 知识图谱

完成资料分块、向量检索、来源引用、Wiki 版本、图节点与边、候选关系确认和跨租户零召回测试。

### 阶段三：SaaS 分层权限与完整评估

完成平台/组织管理、角色与数据范围、前端工作台、运营报表和全量回归。任何管理员越权、跨租户命中或绕过人工关卡都阻止交付。

### 阶段四：外部仓库 1 个 Issue + 1 个 PR

目标仓库必须先由项目负责人确认。选择与本 MVP 直接相关且可复现的一个问题，Issue 说明环境、复现步骤、期望/实际结果、日志和提议方案；PR 关联 Issue，保持小范围修改，附测试、变更清单、文档和截图，遵守目标仓库的贡献指南、许可证和行为准则。

不得为了凑数提交空 Issue、无关 PR、重复 PR 或直接向他人主分支推送。未经确认不代表项目成员对外承诺，不自动合并 PR；评审意见应在原 PR 中继续处理。
